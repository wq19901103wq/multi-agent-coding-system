# 2026-10-10 部署任务重启循环

## 已确认的原因

14:40 起，临时部署任务 `com.mac-system.feishu-pool-fix-20261010`
在 launchd 下以 KeepAlive 方式反复运行。它每次先 stop/start 服务，随后用
两个写死的项目会话 ID 验收。项目实际会话变化后，验收抛出
`AssertionError: project thread identity changed`，任务退出，再被 launchd 拉起。
这使“验收失败”反复触发“停止服务”，而不是只报告验收结果。

21:08 的日志统计为该脚本已确认停服 646 次；现场处置时 launchd runs 已到 647。
这些是同一错误循环的重复执行，不是 647 类独立漏洞，也不包含所有模型流断线。

## 处置与边界

- 卸载错误任务，保留当时已启动的 MAC 主服务 PID 32354，不额外重启。
- 卸载三个已完成的旧部署 launchd 任务；未卸载 MAC 主服务。
- 原临时脚本与两个过期仓库 watchdog 在入口明确拒绝再执行维护动作，正文保留供审计。
- 未清理数据库、项目目录或会话，也未把已变化的会话 ID 改回旧值。

## 防止再次发生

经用户授权的重启走 `bash scripts/restart_server_once.sh <固定操作ID>`：

- 停服前先持久化抢占操作 ID，同一操作最多尝试一次。
- 停服前只读预检 `.env`、端口和启动文件；失败不会停止正常服务。
- 启动等待使用 120 秒耗时预算，不按请求次数估算；非托管旧进程未退出则拒绝接管。
- 启动入口不使用强杀式 kickstart，避免把尚未完成启动误判成需要重启。
- 全局并发锁防止不同部署同时停服；异常死亡留下锁，需人工核查，不自动猜测过期。
- 停止失败、启动失败和后续验收失败都不能抹掉尝试记录，也不能自动换 ID 重跑。
- 验收只读，不绑定固定项目 ID，不调用停服动作。项目未继续执行不等于宿主不健康。
- 一次性维护任务不配置 KeepAlive，完成后卸载；主服务自己的 KeepAlive 可保留。

回归测试覆盖重复调用、停止/启动失败、强杀、并发操作、无效 ID 和过期入口。
补充覆盖 INT/TERM 期间锁的持有与释放、真实预检失败不触发停服、慢健康检查超时，
以及拒绝接管未退出的进程。launchd 输出格式另用本机只读查询核对，非跨版本保证。
服务 HTTP 200 只代表 HTTP 可用，飞书连接和原生执行进展需分别核查；
短时间观察不等于长期稳定性保证，也不替代真实飞书界面测试。

# 同模型续跑：可控化与过程透明化

MAC 不替代 Codex 原生重试。`error.willRetry=true` 仍由 Codex 在当前 turn 内处理；只有原生 turn 已结束且错误属于现有容量不足或连接/断流分类，MAC 才考虑同 thread、空输入追加续跑。不会重发原用户消息、重放已完成工具或切换模型。

启用代理恢复时，原生重连在 120 秒内重复出现传输错误、且首尾相隔至少 30 秒，就会异步检查现有代理恢复路径，无需等待原生 turn 结束。短暂生成进展不会清掉这段故障证据；单次断线、容量或认证错误不会触发切节点。仍沿用全局互斥、冷却和全部目标地址健康检查；工具执行、待审批、用户停止或 turn 结束会取消本地恢复任务。修复网络后由 Codex 继续当前 turn，切节点提示不表示任务完成。

## 有界控制

配置只作用于 Codex Project Lead 的追加续跑，不作用于 Owner 或外部 CLI。无需修改当前 `.env` 即使用默认值；环境变量修改需按正常维护方式重新加载。

| 环境变量 | 默认值 | 范围/意义 |
| --- | --- | --- |
| `CODEX_CONTINUATION_MAX_ATTEMPTS` | 8 | 0–8；0 禁用 MAC 追加续跑，不关闭 Codex 原生重试 |
| `CODEX_CONTINUATION_WAIT_BUDGET_SECONDS` | 2030 | 0–2030；一次调用内追加退避的累计计划等待上限 |
| `CODEX_CONTINUATION_JITTER_RATIO` | 0.1 | 0–1；仅向下随机抖动，不增加原有等待上限 |

各错误使用有界计划：容量不足、明确的 HTTP 429 及 500/502/503/504 最多追加 6 次，退避上限为 30/60/120/300/600/900 秒；连接/断流最多追加 8 次，退避上限为 5/15/30/60/120/300/600/900 秒。短期重试失败后，仍会在 5、10、15 分钟的间隔继续尝试，不需要用户另发“继续”。全局次数或等待预算可进一步缩短计划。下一次完整退避不能放进剩余预算时停止，不延长预算；续跑期间错误分类在可重试类别之间变化（容量不足、连接失败、断流及其上游规范消息形式）不停止，沿用首轮失败的有界计划，不另开一套计划；只有最新失败不再属于可重试类别时才停止。

网络探测失败只说明最近一次检查未连通，不会因连续失败提前终止剩余计划。仍可尝试现有代理恢复路径，并在等待卡中显示“最近一次网络探测未连通；将按间隔自动重试”，保留倒计时、次数和停止入口。网络恢复后沿用原 thread 自动续跑；持续不可达时仍受上述次数与等待预算限制，最终保留 provider 原因。

失败分类优先采用原生终态，不用之前 `willRetry=true` 的中间错误覆盖最终原因。`other` 或缺少分类时，仅识别上游规范的 `stream disconnected before completion:` 和 `exceeded retry limit, last status:` 传输错误格式；不因错误中随意提到“断流”或“重试”就续跑。`responseTooManyFailedAttempts` 同样需要明确的传输原因或可重试 HTTP 状态。账号级并发限制（上游签名 `access_terminated_error` / “concurrent request limit”）是临时拒绝，槽位随在途请求完成而释放，按容量计划（30/60/120/300/600/900 秒，最多 6 次）自动续跑；其余 401/403、额度耗尽、请求错误、权限错误和无法确认的 `other` 不自动续跑；原始 provider 错误事件始终原样保留。此策略只决定是否沿用已有续跑入口，不改变 native turn、工具执行、模型选择或实验脚本自身的恢复方式。

等待预算**不是任务总超时**：不包含 Codex 内部重试、卡片传输、模型生成、工具执行或等待审批。达到预算不强杀已开始的正常执行。

## 用户能看到什么

宿主使用明确命名的 `mac/continuationRetry` 事件记录等待、续跑、恢复、停止或取消，不伪造原生生命周期。已有卡片/outbox 显示追加次数、预计开始时间对应的剩余秒数、等待预算含义，以及停止原因。倒计时随原有进度卡刷新，不按秒刷屏；后续时间线有新交互时仍冻结旧卡，新状态在最新位置展示。

等待中发送 `/stop` 会立即唤醒退避、结束本次追加计划；不会向已结束的原生 turn 发送 interrupt。原 thread 和项目仍保留，下次正常请求不受本次取消影响。运行中的 native turn 仍按原生 interrupt 处理。

成功输出不会因宿主重试提示投影失败而再次执行。失败结果保留 provider 原因，并附上实际追加次数及停止原因。已收到追加计划停止事件时，失败卡首句明确显示“本轮未完成，自动续跑已停止。”，不再仅用“项目可直接重试”让用户误以为未曾自动尝试。没有追加事件时保留原失败提示，不编造重试次数。恢复提示仅在 native turn 真正 completed 后出现，不将“发起重试”当成恢复成功。

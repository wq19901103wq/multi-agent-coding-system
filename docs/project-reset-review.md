# /reset 实现与审查记录（2026-10-10）

## 命令范围

只重置当前选中项目的执行。保留文件、目录、provider、原生会话 ID 和历史；取消旧执行、排队工作、待处理审批及旧 Owner 续推。成功后由用户发送新消息，不自动重放旧任务。

不等待可能堵塞的原生协议或项目锁。清理拥有的进程组、取消并等待宿主任务退出后才报告成功；不能确认时保持隔离并报告失败。未知归属的遗留进程需要维护核查，不按进程名全机杀进程。

首次重置保存旧宿主及后代的 PID、创建时间和已知隔离进程组作为只读见证。服务重启后，只有确认这些旧执行均已退出，才允许无内存句柄的项目解除隔离。见证不是 kill list，不用于终止其他项目。

## 实际 Kimi CLI 审查

审查使用 `kimi-code/kimi-for-coding`，工具限制为 ReadFile、Glob、Grep，禁用 Shell、写入和 MCP。以下是审查摘要，不是 Kimi 实测声明。

1. 第一轮发现重置竞态中的新消息拒绝缺少可见提示，以及带参数命令的提示不准确。已加入专门异常、橙色提示卡、旧代次消息的 outbox 取消通知并补测。
2. 第二轮发现失败重置后再重启服务会永久隔离。未采用直接移除保护条件的建议，因为 `resetting` 也可能表示旧进程仍活着；改为持久化只读进程身份见证，验证退出后再解除隔离。
3. 第三轮聚焦复审结论原文：**“修复有效关闭了上一轮的中等发现，未发现新的具体缺陷。”**
4. 第四轮增量复审覆盖跨线程取消、完成回调与消息循环关闭的先后关系，以及先持久隔离再采集见证的最终顺序；结论原文：**“本轮审查通过，无需要修复的缺陷。”** 本轮为静态审查，未替代真实进程测试。

一次第二轮调用因路径缺少 `src/mac_system`、检索范围未明确而未完成，未作为通过证据；补充准确路径和只读目录范围后重新执行了第二轮。

主审补充：最新实现先建立内存与持久隔离，再采集见证；额外覆盖了快照权限失败仍保持隔离。第三轮文字中关于“首次快照失败发生在围栏之前”的观察对应较早快照，不适用于最终顺序。`killpg(group, 0)` 仅核查组是否存在，不发送终止信号。

真实入口核对补充：飞书消息处理使用独立线程的短生命周期事件循环。重置不再拒绝所有跨线程任务，而是在所属线程注册完成回调后取消，通过线程安全 Future 确认任务退出；不在即将关闭的消息循环里追加等待协程。新增真实线程回归覆盖取消后立即关闭循环的场景。

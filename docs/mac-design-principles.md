# MAC 设计原则

## 1. 产品定位

MAC 是 Codex 原生 coding-agent 体验的飞书移动端、多后端扩展。用户可以像使用 Codex
或 Claude Code 一样连续提出新建、修改、调试和解释需求，同时获得更适合手机的选择卡、
进度卡和结果卡。

MAC 不把软件开发改造成审批流水线，也不要求用户管理 Agent。

## 2. 优先复用已验证实现

- 控制循环、上下文管理、工具调用和多 Agent 协议直接采用 Codex 已验证的实现。
- MAC 只实现产品确实需要、Codex 本身没有的适配层。
- 新增抽象前必须指出上游实现为什么不能满足；没有证据就不自行造轮子。
- 上游已有协议时，工具名、参数、状态和错误语义保持一致。

## 3. Root Agent 就是完整 coding agent

- 用户项目会话直接连接一个持久 Root Agent Thread。
- Root Agent 能直接读写、运行、调试和验证项目，第一轮不降权。
- Root Agent 可使用 Codex 原生多 Agent 工具，但委派不是必经流程。
- 不存在额外的 Coordinator Agent、固定 worker/verifier 数量或专业 Agent 流水线。
- 子 Agent 是持久、可消息和可续接的 thread；是否创建由当前任务决定。

## 4. 动态工作，不预设流程

用户输入直接进入当前 Root Thread。Agent 根据当前代码和真实工具结果决定下一步。简单问题
可以直接回答，局部修改可以直接完成，多个独立任务可以并行委派。

禁止：

- 需求→架构→Spec→编码→测试→Review 的固定状态机；
- 根据关键词、错误文案或任务“复杂度”选择路径；
- R2/R3/R10 式无意义重复 Agent；
- 为单个失败案例增加硬编码兜底；
- 把测试输出和工具日志整包重放到下一轮 Prompt。

## 5. 最小充分上下文

- Root Thread 的历史、压缩和工具结果由 coding-agent 自己管理。
- Child Agent 的上下文使用 Codex 原生 `fork_turns` 语义。
- 外部后端只接收当前任务、必要事实、直接反馈和完成条件。
- 可能有用的历史经验、skills 和参考材料按需加载，不默认整包注入。
- 不在 MAC 中重复实现 coding-agent 的 compaction。

## 6. 用户更少、更方便、更自由地输入

减少的是用户输入成本，不是系统输出：

- 用户可以随时用自然语言补充、纠正、切换话题或继续旧项目；
- 能做选择题时提供 2-3 个清晰选项和推荐项；
- 只有偏好、授权和系统无法取得的外部事实才需要用户回答；
- 未回答旧问题时，新消息仍进入同一 Root Thread，由 Agent判断关联关系；
- 普通内部决策和安全范围内的执行不要求用户审批。

## 7. 输出充分但不暴露内部黑话

所有飞书交互使用卡片：

- 进度卡说明正在做什么和当前真实状态；
- 问题卡显示选择、已选答案和后台等待状态；
- 结果卡说明可见结果、验证和真实阻塞；
- 修改、打断或回答后原卡片状态必须与后台一致。

默认不展示 thread id、task path、提交哈希、测试选择器、协议字段、模型推理过程和原始日志。
用户主动询问时才提供必要技术细节。

## 8. 一个状态一个事实来源

- Codex app-server event 是 turn 和原生 Child Agent 活动的事实来源；
- RootAgentSession 是项目 thread identity 的事实来源；
- QuestionInteraction/QuestionAnswer 是用户问题的事实来源；
- NotificationOutbox/CardProjection 是通知和卡片投影的事实来源；
- Provider 原生 usage 加 MAC 外部后端账单是成本事实来源。

前端不自己维护另一套状态，Prompt 文本也不是状态数据库。

## 9. 自主但不越权

Root Agent 可以完成当前项目范围内正常、可恢复的工程操作。只有以下事项升级给用户：

- 会改变产品方向的偏好；
- 新的敏感或外部授权；
- 系统无法观察的外部事实；
- 不可恢复或明显超出当前项目范围的动作。

私人本地项目不做脱离实际目标的企业级安全、分布式、迁移或治理设计。

## 10. 黑盒优先验证产品能力

自动测试用于快速发现回归；真实飞书私聊和生成项目入口用于证明产品体验。对生成项目的修改
必须通过 MAC 完成，外部开发者不能直接替项目修代码。MAC 表现异常时可以检查 MAC 日志和
必要的生成项目证据，但修复必须发生在 MAC 层并覆盖同类问题。
